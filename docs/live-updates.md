# Live updates

The authenticated project event stream reports committed revisions. The browser uses a bounded SSE parser over fetch so X-Ledger-UUID remains required. The shared service wakes watchers only after commit; a shared project reconciliation task checks durable state after missed wakeups. Streams do not extend session idle life. Limits are eight streams per principal, 32 overall, one pending state per subscriber, 15-second heartbeats and five-second reconciliation. Graceful server shutdown is bounded at five seconds.

The dot beside the project selector in the Decisions or Projects heading is green when displayed data and a correctly bound live state match, yellow when results/context are stale, red when the selected record is stale, and gray when freshness cannot be established. Notification receipt updates the indicator. Eligible yellow state can schedule the guarded read refresh below. Red selected-record changes require explicit review; notifications never change editor fields or save preconditions. Project/default selection binds the displayed decision key, with one stream per tab.

**Refresh results** collects filtered results, the same selected saved record, its collections and context before replacing the display. Responses must share a project identity and ledger revision. Collection retries at most once within a 20-second overall budget; a superseded or failed collection retains the previous coherent display. Filters, selection, scroll and surviving focus are preserved. Completion waits for a live frame at least as new as the collected snapshot; newer concurrent changes remain actionable. In Projects, heading Refresh and popup Refresh results use the same coordinator. They collect the catalog, enabled selected-project summary and complete Sources inventory before committing a revision-consistent display; the catalog is checked again before commit. No selection or disabled inspection still permits catalog refresh and preserves a different operational project. Projects has its own ledger freshness baseline and a no-selected-record stream; it does not clear a stale Decisions cache. The dot does not promise continuous catalog-change discovery. Missing planning-root registration is shown as an explicit Sources configuration state while the overview remains usable. An actual required read failure retains the previous coherent display, marks freshness unestablished and shows the failed region with Retry in the visible pane. Artifact, candidate, planning and history actions keep their existing scopes.

While the editor is modal, use **Review workspace updates** inside the editor. It opens review above the draft. Refresh results updates results and presents a saved comparison without replacing editor fields, its saved baseline, revision preconditions or retained request. Review changes presents differences. **Rebase draft for review** explicitly installs the reviewed saved baseline/context and advances save preconditions while retaining typed fields; Save remains separate. Rebase rechecks current saved revisions and transition eligibility, and is blocked during saving or an uncertain pending outcome. Retry original save resolves retained requests first. Remote closure/protection blocks substantive drafts until the existing Reopen/Amend workflow permits them. Supporting-context drafts may be explicitly rebased for review only when the current operation, record and relationship endpoints remain eligible under `closed_context_v1`; rebase never saves automatically. Without an editor, **Use latest** invokes coherent refresh.

**Retry connection** waits for verified readiness and reconciles data without a page reload; it stays in the popup until the outcome is known. Controls adapt to connection changes while the popup is open. Refresh remains available during transient disconnection when authorization is usable. Confirmed session expiration automatically shows Sign in and retains the draft and pending request for explicit review after authentication. A failed fetch performs one bounded session check; an outage alone does not establish expiration. Permission or identity failures remain unavailable. An explicitly stopped service retains its Start action. Persisted page restoration resumes monitoring; yellow synchronization remains subject to every guard below and never changes drafts.

## Safe yellow synchronization

Decisions and Projects automatically refresh read-only results/context after one second without input or a relevant notification. There is one in-flight collection, one coalesced pending notification and at most one automatic start per five seconds. Each attempt uses the same 20-second total budget and at most one consistency retry. Library keeps its independent explicit refresh and staging rules.

Automatic refresh waits while a dialog/editor, draft, pending/uncertain save, project operation, text selection, editable focus, pointer/key interaction, scrolling or expanded History/Source/details is active. It rechecks eligibility, identity and the latest observed live revisions immediately before commit. Selected revision changes or disappearance remain red and are never automatically applied. Filters, loaded result extent, selected key, scroll, layout and surviving focus are preserved; unsafe restoration defers to explicit Refresh. Hidden tabs issue no automatic refresh requests.

Navigation or new interaction cancels automatic work without replacing the display. A failed automatic attempt pauses synchronization for that project/view binding until a successful explicit Refresh or Retry. Navigating away and back does not reset the pause. There is no automatic save, rebase, retained-request change, backend start or background catalog polling. A concurrent event after commit may make the dot yellow/red again; green describes the displayed data against the latest verified state, not future commits.

The rounded half-shaded focus square remains fixed below the header, toggling the context/results panel. The former main-detail Results and Focus buttons are removed. Keyboard controls, tooltip and pressed state express the same action. The icon is 18px at 60% resting opacity within a 44px target and returns to full emphasis on hover/focus. At 980px or narrower it disappears; the stacked panel stays visible and has no collapse toggle.

## Projects open-decision indicator

The steady project-list dot means the project has at least one open decision. Zero open decisions hides it. Clicking a project, visiting Decisions and browser storage have no effect on this rule. The marker keeps its fixed gutter and accessible Open decisions description.

The browser reads existing project-summary counts on Projects entry/manual Refresh, with at most two concurrent requests and the existing five-second request/20-second sweep bounds. Selected-project live refresh may update its row. No polling or new streams are added. Unavailable counts show no dot and an accessible Refresh-to-retry description; disabled projects are not read. Old acknowledgement storage is inert and is neither read nor written.
